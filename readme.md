## 一、程式用途與執行方式

### 程式用途
本程式為「兩場活動報名整理器」，針對「桌遊體驗」與「電影欣賞」兩場活動收到的原始逗號分隔名單，進行以下自動化處理：
1. **資料清理**：利用字串方法移除半形空白、統一轉小寫，保留原始資料不覆蓋。
2. **容器運用**：
   - `tuple`：保存不可變動的兩場活動名稱。
   - `list`：保存清理後、仍保留重複報名紀錄的清單，以及排序後的名單。
   - `set`：去除同一場的重複報名者，並透過交集、聯集與差集比較兩場活動參加者。
   - `dict`：儲存各活動單價，以及彙整最終人數、人次與應收金額摘要。
3. **格式化輸出**：透過 `f-string` 產出包含名單預覽（切片）與精確至小數點後兩位金額的完整報告。

## 三、個人問題回答

### 問題一：測試一中，整理後的桌遊串列有 4 筆資料，為什麼桌遊費用應以 3 人計算？直接把字串拆成 list，和再轉成 set，各自保留了什麼、失去了什麼？
- **費用計算原因**：根據活動規則，同一個人在同一場活動中重複報名（如 `"Amy"` 與 `"amy"`），只能算作一位參加者，也只能收取一次該場費用，因此去重後實際參與桌遊的是 3 人（`amy`、`ben`、`cora`），應收 `3 × 120 = 360` 元。
- **轉成 `list` 與 `set` 的差異**：
  - **直接拆成 `list`**：**保留**了報名的先後順序以及重複報名的次數（例如知道 `amy` 填了兩次表單）；但**失去**了唯一性，無法直接得知實際不重複人數，也無法直接進行集合比較。
  - **再轉成 `set`**：**保留**了所有不重複的獨立參加者名單（唯一性），並獲得交集、聯集、差集等高效比對能力；但**失去**了原本的報名順序以及重複報名的次數紀錄。

### 問題二：測試三中，兩場活動只有 3 位不同的人，為什麼是 6 人次、總應收仍是 600 元？請用集合關係與算式說明。
- **集合關係說明**：在測試三中，桌遊集合 $A = \{\text{amy}, \text{ben}, \text{cora}\}$，電影集合 $B = \{\text{amy}, \text{ben}, \text{cora}\}$。兩者的聯集 $A \cup B$ 與交集 $A \cap B$ 完全相同，元素個數（總不重複人數）皆為 $3$ 人，且兩個方向的差集（$A - B$ 與 $B - A$）皆為空集合 $\emptyset$。這代表這 3 位參加者**同時報名了兩場活動**。
- **人次與金額算式**：因為規則規定「同一人參加兩場需分別計費，且算作兩人次」，所以計算方式如下：
  - **報名人次** $= |A| + |B| = 3 + 3 = 6\text{ 人次}$
  - **總應收金額** $= (3 \times 120) + (3 \times 80) = 360 + 240 = 600\text{ 元}$
